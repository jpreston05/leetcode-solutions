For this question we need to serialise a list of strings into a single string and recover the original list from it. The problem is that any character we pick as a separator could legitimately appear inside one of the strings, so a separator alone is never enough. We solve this by length-prefixing: before each string we write its length, followed by a `\` delimiter, followed by the string itself. The delimiter is only there to mark where the digits of the length stop.

In `encode` we iterate over `strs` and build up `output` as `str(len(s)) + "\" + s` for each string.

In `decode` we walk the encoded string with a pointer `i`. At each step `i` sits at the start of a length prefix, so we read characters into `length_str` until we hit the `\` delimiter, then step over the delimiter itself and convert the digits to an integer. Because we now know exactly how many characters the next string occupies, we can slice it directly with `s[i : i + length]` and jump `i` forward by that length, landing on the start of the next prefix. This is what makes the encoding safe — we never scan through the content looking for a delimiter, so a `\` appearing inside one of the original strings is simply consumed as part of the slice and never mistaken for a separator.
```python
class Solution:

    def encode(self, strs: List[str]) -> str:
        output = ""
        for s in strs:
            output += str(len(s)) + "\\" + s

        return output

    def decode(self, s: str) -> List[str]:

        output = []
        i = 0

        while i < len(s):
            length_str = ""

            while s[i] != "\\":
                length_str += s[i]
                i += 1

            i += 1
            length = int(length_str)

            string = s[i : i + length]
            output.append(string)
            i += length

        return output
```
> Time Complexity : `O(n)` for both encode and decode, where `n` is the total number of characters
> 
> Space Complexity : `O(n)`
